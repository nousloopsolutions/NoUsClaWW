# NoUsClaWW Governance

**Status:** Canonical — applies to all agents operating on NoUsClaWW.
**Authority:** Brent (hovlandbr) — sole merge authority.
**Scope:** All repos under `nousloopsolutions/NoUsClaWW`.

---

## 1. Purpose

This document is the root governance charter for NoUsClaWW. It defines the rules, invariants, and operational constraints that all agents (human and AI) must follow. It is referenced by every other governance document in this repository.

## 2. Prime Axiom

**Safety Through Severance** — the agent never directly handles untrusted data. Six Virtual Severance Domains (VDS) enforce isolation at every boundary. This axiom is immutable and cannot be overridden by any agent, review, or automation.

## 3. Four Axioms

1. **Local-First** — runs on your machine, no cloud account required
2. **LLM-Agnostic** — works with Ollama, Claude, OpenAI, or any provider
3. **Open Process** — every decision documented, every source credited
4. **Epistemic Boundary + Silence Protocol** — agent knows what it doesn't know, stays silent on low confidence

## 4. Open Core Boundary

- **Public (Tool):** `/src/community/` — community-contributable code
- **Private (Brain):** `/proprietary_core/` — gitignored, never committed
- **Immutable Interface:** `/src/sovereign_sockets/` — the boundary contract, changes require ADR

No agent may cross this boundary. No automation may import proprietary code into community code. The DAG is enforced by CI.

## 5. Agent Roles

| Role | Responsibility | Authority |
|------|---------------|-----------|
| **Builder Agent** | Implements features, fixes bugs, writes tests | May create branches, push, open PRs |
| **Review Agent** | Independent code review, security audit | May approve/request changes on PRs |
| **Verification Agent** | Runs CI gates, 10K test, axiom-synth checks | May fail/pass CI checks |
| **Adjudication Agent** | Final automated readiness assessment | May post READY_FOR_PHASE_REVIEW |
| **Brent (hovlandbr)** | Merge authority, production deploy, axiom changes | Sole merge authority |

## 6. Automation Principle

The workflow is **maximally automated**. Brent's only touchpoints are:

1. **Final merge approval** — when a PR reaches `READY_FOR_PHASE_REVIEW`
2. **Axiom/scope changes** — any change to prime axioms, architecture, or privacy boundaries
3. **Production deployments** — DNS, secrets, credential rotation
4. **Destructive operations** — irreversible changes

Everything else — test failures, lint fixes, dependency upgrades, documentation drift, CI repairs — is handled autonomously by agents.
